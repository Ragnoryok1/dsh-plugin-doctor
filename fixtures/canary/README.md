# Фикстура: заведомо сломанный плагин

Плагин диагностики утверждает, что умеет находить неработающие плагины. Такое
утверждение ничего не стоит без **настоящей поломки**, поэтому здесь лежит
плагин-канарейка: его `apply()` всегда бросает исключение, а профиль объявляет
его строку. Установка канарейки даёт панели то, что она обязана найти.

## Как повторить проверку

```powershell
# 1. собрать пакет (lib/index.js уже готов, сборка не нужна)
cd fixtures/canary
npm pack

# 2. поставить в профиль
dsh plugin --profile web add .\ragnoryok1-dsh-doctor-canary-0.0.1.tgz

# 3. открыть Настройки → Встроенные плагины → Диагностика
#    ожидается: «Найдена 1 проблема» и раздел
#    «Объявлены, но не запущены (1): doctor-canary»

# 4. убрать за собой
dsh plugin --profile web remove @ragnoryok1/dsh-doctor-canary
```

После удаления панель обязана снова показать «Проблем нет».

## Что именно ловится

Упавшая на хосте строка не попадает в список живых плагинов, поэтому сообщение
об ошибке показать некому — срабатывает проверка **строк бандлов**: строка
объявлена, а живой записи у неё нет. Это ровно тот след, который оставляет
неудачное обновление.

Именно так и было проверено: с установленной канарейкой панель показывала
«Найдена 1 проблема» и называла `doctor-canary`, после удаления — «Проблем нет».
